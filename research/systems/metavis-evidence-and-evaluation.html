Research/Evidence-Governed AI Systems

The Video Looks Right. What Did the Software Check? ​

A polished frame can hide a missing soundtrack or an expensive rendering loop. The tests in my video editor gave each failure a different way to show up.

Keith Williams · Engineering case study

Share on LinkedIn

In MetaVis, my Swift and Metal editing prototype, one test renders a pattern and checks its frame hash. Another inspects the exported media, manifest, and quality reports. An editor needs both answers. The image can have the expected pixels while the delivered clip is silent.

Would you sign off on an export marked accepted: true? In one path through the optional Gemini check, that is the recorded verdict even when the reviewer never saw the clip. If the policy disallows sending media, the accompanying text says the check was skipped. I would give each promised check a visible passed, failed, or untested state. That change is proposed. Today, a reviewer must read the skip message to interpret the verdict. Gemini verdict code · Prototype audit

Architecture ​

The system translates editing intent into a typed timeline, then compiles the timeline into a render graph. A model can propose a change. Swift code applies a defined operation. That boundary makes the change easier to reproduce and undo. The code separates media ingestion, rendering, perception, export, and quality control. The design critique also flags an abstraction that can cost too much in a real-time render loop. Swift packages · Editing design · Architecture critique

Tests as instruments, not decoration ​

A question a reviewer can askThe experiment in code
Did the same input produce the expected pixels?Render a reference pattern and compare its frame hash
Does the GPU path agree with a reference implementation?Compare the Metal output with a reference buffer
Can the same clip produce different sensor readings?Ingest the media twice and compare the results
What happens after the first frame?Check allocations after warm-up
What would a recipient actually receive?Inspect the exported media, manifest, and quality reports

These are different claims about one deliverable. A project can choose its most consequential claim first and give someone a repeatable check before adding another model to the workflow. Test strategy

Deterministic measures and qualitative Gemini review ​

The quality-control modules measure properties such as frame count, silence, temporal variety, and image statistics. An optional Gemini reviewer then gets the intended narrative, selected media, and the measured results. It can question whether an exposure correction suits the scene. The program still enforces which parameters may change. Video measurements · Content checks · Gemini review · What the reviewer receives

The Sprint 16 design budgets how much evidence leaves the system. It selects frames, short audio or video snippets, and sensor summaries. A reviewer can request another sample when those are insufficient. One useful disagreement is a numerical exposure heuristic and a model that sees an intentionally dark scene. I want that disagreement available to inspect before changing the image. Evidence packet design · Exposure heuristic · Allowed edits

Hardware optimization as an engineering boundary ​

The design assigns suitable work to Apple media engines, Core ML/Vision, and Metal and reuses buffers to limit copies. The shader-performance sprint notes report measurements on an Apple M3. They document that setup and workload. A claim about comparative performance would need a controlled test on the systems being compared. Hardware design · M3 measurements

Gaps and research implications ​

The prototype audit identifies mock services and unfinished AI paths. Some media fixtures sit outside the public repository, and some tests require particular hardware. Anyone reproducing the checks should record which fixtures and hardware they used. Read the audit

My research question is whether a few well-chosen measurements, followed by a bounded qualitative review and human acceptance, can catch consequential mistakes with less review effort. The code gives me a place to run that comparison.
