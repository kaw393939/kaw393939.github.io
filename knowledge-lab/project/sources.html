Reference map ​

An API manual tells you what a library permits. A pinned source line tells you what one implementation did. A test run answers a third question.

Share on LinkedIn

LinkedIn opens a draft you can review before posting.

Start with the kind of claim you need to check. To understand the behavior of a donor module, use its pinned source and inspection range. For the semantics of a database or protocol, use its primary documentation. To say the new application works, ask for a run of that application.

The authoritative reuse map is the pinned source audit, not a moving README. It separates historical Rust implementation, current rebuild contracts and owner-only executor work. No donor runtime test-pass claim is made by the audit.

For a lease review, inspect the historical job kernel in the pinned source audit, then run the lease exercise at a recorded Lab revision. Cite the donor lines for the original behavior and the command output for what the public exercise actually checked.

The private executor lab and server manual remain owner-only sources. They are not build dependencies, required student access or content to copy into a public fixture archive.

Primary technical sources ​

The twelve-factor matrix links each original factor separately. Other primary references are SQLite portability, backup API, WAL, Rust ABI, Cargo builds, SSE, VitePress deployment and GitHub Pages workflows.

Use current official instructions when changing dependencies, infrastructure or account settings. A reference link is not evidence of an executed deployment.

Evidence policy ​

For a review note, write down the claim first and then the evidence that supports precisely that claim. “This revision contains a lease check” and “a late result was rejected in a restart test” need different citations. This page helps find the first, and the acceptance record should carry the second.

A source inspection, authored example, executed test, published artifact and live observation are different levels of evidence. Preserve the commit, command, fixture, platform and limitations for each. New examples are synthetic. UFO testimony is recorded as testimony; neither an LLM score nor agreement among copied reports establishes scientific truth.
